01
PAYMENT FLOW

ONE PAYMENT. THREE OUTCOMES.

The customer pays on Recurrente's hosted page. Odoo then reads the payment from Recurrente's API, also triggered by a signed webhook, and marks the transaction as paid, pending or failed.

CHECKOUT → RECURRENTE API → ODOO
Neither the browser redirect nor the webhook body is trusted: the state is always fetched with your secret key.
02
CAPABILITIES

PAYMENTS

Hosted checkout for website sales, invoice payment links and customer portal payments. GTQ and USD. Card data never reaches your Odoo server.

SAVED CARDS

Save a card while paying, then charge it again when Odoo asks for it, for example from Subscriptions. Failed charges report Recurrente's reason.

REFUNDS

Full and partial refunds from the transaction (partial when the processor allows it). Requests carry an idempotency key, so a retry never refunds twice.

SECURITY

Signed (Svix) webhooks, API verification, test and live keys kept apart, and credentials cleared when a database is neutralized.

03
SETUP

FIVE MINUTES TO THE SANDBOX

01Install the module and open Accounting > Configuration > Payment Providers > Recurrente.
02Paste the secret key: sk_test_... for a Sandbox, sk_live_... for real payments.
03In Recurrente, register a webhook to https://your-domain/payment/recurrente_api/webhook with the intent.* events and refund.create. Paste its signing secret (whsec_...) in Odoo.
04Set Test Mode and run a Sandbox payment with the card 4242 4242 4242 4242. Enable the provider when ready.
05Optional: enable Allow Saving Payment Methods so customers can save their card.

05
DATA SENT

DATA SENT TO RECURRENTE

This module connects Odoo to an external service. When a customer pays, Odoo sends to Recurrente's API:

  • The amount, the currency and the transaction reference.
  • The product lines (name and price) and your company name as the payment description.
  • The return, cancel and webhook URLs of your Odoo database.
  • Your secret key, only as the authentication header of each request.
  • For a saved card: the Recurrente payment-method id, never the card number.

Card details are typed on Recurrente's page and never pass through Odoo. Logs keep identifiers only, no names, emails or phones.

06
BOUNDARIES

BEFORE PRODUCTION

Account required. A Recurrente account is required for the provider to operate.
Saved cards. Charging them needs one-time payments with a saved payment method enabled for your account; ask Recurrente if it is not. Cards are saved while paying; adding one without paying is not available yet.
Refunds. Card and Recurrente Balance payments only, within 30 days and with enough balance; the processing fee is not returned. Partial refunds depend on the card processor.
